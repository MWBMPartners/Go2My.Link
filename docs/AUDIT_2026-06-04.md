# 🚀 Go2My.Link — Final Deployment-Readiness Audit Report

**Date:** 4 June 2026
**Auditor:** Automated deployment-readiness review (Claude Code)
**Repository:** https://github.com/MWBMPartners/Go2My.Link
**Build state at audit:** Component A tagged `v1.0.0-rc`; Component B core redirect engine working; Component C not yet built
**Language standard:** British English (en-GB)

---

## 1. 📋 Executive Summary & Overall Verdict

Go2My.Link is a well-architected, multi-component URL-shortening platform built in disciplined phases. The codebase that has shipped to `v1.0.0-rc` is genuinely solid: MySQLi prepared statements throughout, AES-256-GCM encryption of sensitive settings, robust local authentication, DB-backed sessions, organisation management with DNS-verified domains, GDPR-style compliance tooling, and a careful security-hardening pass (issues #80–#90, all verified intact and not regressed).

However, **the platform is NOT ready for an unconditional production launch as it stands.** There is **one CRITICAL/HIGH issue that must be resolved before any `git add`** — an untracked legacy file containing a **plaintext live production database password** that is not covered by `.gitignore` — plus a small cluster of medium-severity, fixable defects in the launchable surface (a functional bug that breaks link editing, a contact-form mail-injection vector, a missing CAPTCHA check, and a CSP that breaks Component B's own error pages).

**Overall verdict by component:**

| Component | Domain | Verdict | Headline blockers |
|---|---|---|---|
| **A** — Main site + Admin | go2my.link / admin.go2my.link | 🟡 **READY-WITH-FIXES** | Link-edit `notes`/`urlNotes` bug; contact-form CRLF injection; contact-form CAPTCHA not verified |
| **B** — Shortlink router | g2my.link | 🔴 **NOT-READY** (blocked) | Plaintext DB password in `public_html_legacy/`; favicon always 404s; CSP blocks error-page CSS |
| **C** — LinksPage | lnks.page | ⛔ **NOT-READY (by design)** | Product not built (Phase 8 not started) — must not go live as a product; landing page only |

The honest framing: this is a **minimum-launchable product (Components A + B)** with a large, *intentionally deferred* roadmap (API, analytics, advanced redirects, social/2FA/SSO, payments, and the entire LinksPage product). The code and the documented roadmap are internally consistent. The launch decision therefore hinges on the small set of P0/P1 fixes below, not on the deferred phases.

## 2. 🧭 Per-Component Deployment Verdict & Go-Live Checklist

### 2.1 Component A — go2my.link (main site + admin dashboard) — 🟡 READY-WITH-FIXES

Component A is the most complete and is close to launch-ready. Core flows (anonymous + authenticated link creation, auth, org management, privacy dashboard, legal pages) are implemented and lint-clean.

**Blocking items before go-live:**

- [ ] **Fix link-edit bug** — `web/Go2My.Link/_admin/public_html/pages/links/edit/index.php` UPDATE references a non-existent column `notes`; the schema column is `urlNotes`. **Every link edit currently fails silently** ("Failed to update link"). This disables a core dashboard feature. (P0 functional)
- [ ] **Patch contact-form CRLF header injection** — `web/Go2My.Link/public_html/pages/contact/index.php` passes an unsanitised `$contactSubject` (with embedded CR/LF possible) into `mail()`, enabling header injection / open-relay abuse. (P0 security)
- [ ] **Verify CAPTCHA server-side on the contact form** — the Turnstile/reCAPTCHA widget is rendered but never validated server-side; the only protection is a spoofable per-IP rate limit. (P1 security)

**Recommended before launch:**

- [ ] Add a branded `pages/errors/404/index.php` (only 400/403/500 exist; `.htaccess` routes 404 to a non-existent page, falling back to the unstyled inline block).
- [ ] Fix the landing-page logo `alt` text (`public_html_landing/index.php` uses undefined `$siteName`, producing empty `alt`).
- [ ] Add `@media (prefers-reduced-motion: reduce)` to `css/style.css` and gate `app.js` smooth-scroll on it (WCAG 2.3.3).
- [ ] Convert account-deletion cancellation to a CSRF-protected POST.

### 2.2 Component B — g2my.link (shortlink router) — 🔴 NOT-READY (blocked)

The core redirect engine works (issues #8, #10, #11, #13 all verified implemented), but Component B carries the single most serious finding in this audit and two functional/cosmetic defects that affect every visitor.

**Blocking items before go-live:**

- [ ] **CRITICAL — Remove the plaintext production DB password.** `web/G2My.Link/public_html_legacy/dbConfig.php` contains a live MySQL credential in plaintext, is untracked, and is **NOT** matched by any `.gitignore` rule. One careless `git add .` commits a live secret into history. **The credential must be treated as compromised and rotated.** (P0)
- [ ] **Fix the default favicon 404** — `web/G2My.Link/public_html/favicon.php` line 122 falls back to `favicon_default.ico`, which does not exist. **Every favicon request to g2my.link returns 404.** (P1)
- [ ] **Fix the CSP/CSS mismatch** — `web/G2My.Link/public_html/.htaccess` CSP (`style-src 'self'`) blocks the CDN Bootstrap/Font Awesome stylesheets that `404.php`, `expired.php` and `validating.php` load, so the branded error pages render unstyled. (P1)

**Recommended before launch:**

- [ ] Apply the `^https?://` scheme allowlist to destination/fallback URLs in `validating.php`/`expired.php` (defence against `javascript:` schemes in migrated legacy URLs).
- [ ] Add a path-traversal guard (`basename()`/`realpath()` containment) in `favicon.php` before any `readfile()` (latent, becomes live when org-logo upload is built).
- [ ] Remove the redundant `aria-live` on the per-second visible countdown in `expired.php`/`validating.php`.
- [ ] Set `lang="en-GB"` (and `dir="ltr"`) on the three error pages.
- [ ] Add `ErrorDocument` directives for branded server-level error handling.

### 2.3 Component C — lnks.page (LinksPage) — ⛔ NOT-READY (by design)

Component C is **scaffolding only.** `web/Lnks.page/public_html/index.php` reads `?slug`, logs `linkspage_view`/`not_implemented`, and returns a 404 placeholder for any slug; there is no renderer, no template consumption, no upload, and no age-gate. The DB tables (`tblLinksPages`, `tblLinksPageItems`, `tblLinksPageTemplates`) have **zero PHP references.**

**Go-live position:** The LinksPage **product** must NOT be advertised or launched. Only the coming-soon landing page may be served. If the landing page is shown publicly, the following landing-page accessibility blockers apply:

- [ ] **Remove/replace the unconditional 15-minute `<meta http-equiv="refresh">`** (`public_html_landing/index.php` line 30) — WCAG 2.2.1 (Timing Adjustable, Level A) failure; reloads discard the email field and reset focus. (P1 a11y)
- [ ] **Honour `prefers-reduced-motion` in the JS countdown-ring loop and auto-refresh** — the CSS query gives a false impression of compliance while the `requestAnimationFrame` ring keeps sweeping. (P2 a11y)
- [ ] Either wire the "notify me" form to a real backend or replace it (currently `action="#"`, silently discards the address).
- [ ] Fix the `<picture>` PNG fallback (both `<source>` and `<img>` point at `logo.svg`).
- [ ] Add `@media (forced-colors: active)` fallback for the gradient-clipped `h1`.
